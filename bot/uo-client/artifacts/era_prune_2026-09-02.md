## 5. The one-off — how to run it at restart

File: `runtime/scripts/revolution/f_era_prune_wardrobe.scp` (loads
automatically — `spheretables.scp` includes `revolution/`).

**It has NOT been run.** Shard is down.

1. Start the shard.
2. At the server console type exactly:

       .f_era_prune_wardrobe

3. Expect one `@EraPrune ::` log line per defname plus a final total, ending
   around `483 removed`.
4. Then:

       .save

5. Verify from the repo root:

       python tools/world_query.py --count i_hakama_tattsuke   -> 0
       python tools/world_query.py --count i_boots_tabi        -> 0
       python tools/world_query.py --count i_shoes_tabi        -> 0
       python tools/world_query.py --count i_hakama            -> 0
       python tools/world_query.py --count i_hat_kasa          -> 0
       python tools/world_query.py --count i_elven_male_robe1  -> 0
       python tools/world_query.py --count i_gargish_stone_arms-> 0
       python tools/world_query.py --count i_helm_garland      -> 21   (unchanged — AOS, in era)

What it does: for each of 41 out-of-era defnames it walks `FORINSTANCES`, and
for any instance whose `TOPOBJ` is a **non-player** char it records the layer,
removes the item, and re-dresses that layer from the pruned human pool in
`tm_generic.scp` (`random_footwear_human`, `random_pants_human`,
`random_shirts_human`, `random_hats`, `random_tunics_manly`,
`random_robes_human`, `random_skirts_human`) in `colors_newbie_clothing`.
Weapon layers are emptied and left empty on purpose.

`ISPLAYER` guard: anything owned by a player — which includes every bot
character in `roster30.tsv` and its gear — is skipped. Loose world items and
container contents are deleted but nothing is re-equipped for them.

Counters are held in `VAR.` not `LOCAL.`, and the owner char is re-addressed
by `UID.<hex>.<command>`. This is the trap documented in
`revolution/f_m39_prune_ml.scp`: inside a `FOR<object>` loop the default
object is the loop object, so `LOCAL.` addresses that object's own variables
and dies with it — a previous prune reported "removed 00" while deleting nine
objects. Safe to run twice.
