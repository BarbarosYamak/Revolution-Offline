# TAME_ANIMAL: names before judgement, pastures from the table (2026-09-02)

## Root cause, confirmed in source

`Runner::DoTameAnimal` filtered `client.ScanMobiles(12, nearby)` with
`if (m.name.empty()) continue;`. A mobile name only exists in this client after
the 0x98 AllNames query issued by `Client::ActionScanMobiles` ->
`Client::PrintNearbyMobiles` (`src/Client.cpp:5697-5712`); `ScanMobiles` only
reads the cache (`src/travel/ClientTravel.cpp:2450`). The taming path never
issued the query, so every sheep was nameless and every pasture read empty.

Second, `kPastures` was three compiled-in literals `{572,1098},{669,943},
{669,1175}` walked in fixed order. `data/revolution_pastures.tsv` (4 rows,
generated by `tools/pasturegen.py`) was already loaded by Runner.cpp's own
`LoadPastures`/`Pastures()` (`src/life/Runner.cpp:361-391`) for the wool chain
— the taming path just did not use it, and its literals do not match the file
(572,1096 / 677,1177 / 681,945).

## Fix

- `include/uo/activities/tame.h` (new, header-only pure):
  - `MayJudgeEmpty(TameScanSight, settleMs)` — the seam: no emptiness verdict
    unless the scan was issued, no 0x98 replies are pending, and the settle
    window has passed.
  - `OrderPasturesNearest(list, x, y)` — nearest-first, ties to the bigger flock.
- `src/Client.h` — `bool MobileNamesPending() const` exposes
  `mobilesListPending_` so a caller can tell "no names yet" from "no animals".
- `src/life/Runner.cpp DoTameAnimal`:
  - issues `ActionScanMobiles` when `tameScanMs_ == 0` (first tick, and again
    after every pasture trip), waits 2000 ms (`kTameSettleMs`) and for the 0x98
    replies before any verdict;
  - reads the pastures via `LoadPastures`/`Pastures()`, orders nearest-first,
    drops the flock it is already standing in, keeps the 3-trip cap
    (`kMaxTameTrips`), literals kept only as a data-missing fallback;
  - reads the shard's answer to the previous attempt out of the journal
    (`JournalHeardSince(tameAskedMs_)`): success = "…as master" /
    "…as it's master" -> `tame: success`, `NoteProgress()`, `Finish(true)`;
    refusals ("too many followers", "cannot be tamed", "is already tame",
    "you can't tame", "your own master") -> the server line is logged as the
    reason and the goal stands down;
  - bounded retries, `kMaxTameAttempts = 8` (Sphere rolls 2-5 strokes,
    `CCharSkill.cpp` `m_atTaming.m_dwStrokeCount`; `@Fail` in
    `skills/skill35_taming.scp` is an ordinary outcome).

Message strings verified in `runtime/scripts/core/messages.scp:911-922` and
`server/Source-X/src/game/chars/CCharSkill.cpp:2263-2400`.

## What happens to a tamed pet

Sphere does it: `Skill_Taming` SKTRIG_SUCCESS calls `NPC_PetSetOwner(this)` and
`pChar->Skill_Start(NPCACT_FOLLOW_TARG)` (CCharSkill.cpp, end of the function).
The pet follows its new master by itself. This runner has no pet system and
none was added — the goal records the tame, credits progress and stands down.

## Runtime evidence

`run_gates/g_Rhea.console.txt`, run 1 (12:04-12:10, 5 min):

- :127 `tame: reading the names of everything nearby before judging this spot
  (Taming 50.0)` — the scan the old code never issued
- :133 (2.0 s later, not 60 ms) `tame: nothing tamable here -- 3 named
  mobile(s) in sight, none tamable at Taming 50.0; walking out to the flock of
  15 at 677,1177 (714 tiles, trip 1)` — 677,1177 is a TSV row, not one of the
  old literals, and it is the nearest one
- :541-542 `[travel] pasture ARRIVED at (692,1188)` `travel_done label='pasture'
  ok=1` — the arrival landed exactly at the session limit, so no taming attempt
  fitted into the 5-minute window.

Run 2 (12:10-12:15) never picked TAME_ANIMAL: the character was killed on the
road during run 1 (`g_Rhea.err.txt` THREAT lines 12:09:31-12:10:09) and spent
the whole session on SURVIVE / HEAL / REPLACE_EQUIPMENT at 4/32 hp
(`session_goals families=2 picks=10 ... SURVIVE=1 HEAL=4 REPLACE_EQUIPMENT=5`).

So: the "no judgement before names known" fix and the data-driven nearest-first
pasture choice are proven at runtime. `ActionUseSkill(taming)` + the server's
reply are NOT yet proven — they need a session that starts at the flock in one
piece.
