# M3.9 -- prove a bot can kill something, WITH A WEAPON.
#
# RUN AS AN ARMED FIGHTER SESSION (53+ / RevolutionFighter03+). Sessions 51 and
# 52 are dead and stripped: 51 was executed by guards for hunting livestock,
# 52 lost a fair fight to an awake grey wolf after standing through 12s of
# free hits (see the scan-wait note below). Each new fighter is created the
# ordinary way with -CreateSkills 'Swordsmanship=50,Tactics=30,Anatomy=20'
# -CreateStats '55:15:10'.
#
# WHY A NEW CHARACTER INSTEAD OF RevolutionSpar
#
# Six runs proved that targeting works and the server accepts it --
# `[0xAA] attacking 0x00000856`, `attack success ... server accepted the target`
# -- and that nothing ever died. Attempt 6 also disproved the obvious mechanical
# explanation: the attack was sent ONCE and the bot merely kept in range, so the
# swing timer was never reset, and the dog lived anyway.
#
# The remaining explanation was mundane. Spar died at the Britain cemetery and
# FULL LOOT LOSS took its weapon, so it had been punching with Wrestling at
# STR 30. It could not buy a replacement either: `mark_gold = 0`. Full loot loss
# means exactly that.
#
# So this is a fresh character built the ordinary way. The Swordsmanship request
# is not about the skill, it is about the KIT: [NEWBIE SWORDSMANSHIP] in
# sp_tm_newbie.scp grants i_katana -- 0x13FE, DAM 11-13, ReqStr 25, DUPELIST
# 013FF for the flipped graphic. Against unarmed Wrestling that is the whole
# difference. Source-X clamps the requested skills and stats itself
# (CChar::InitPlayer), so nothing here is granted beyond what the shard hands
# any new player.

wait_world
sleep 2500
ensure_peace
gait run

request_skills
sleep 1500
skill_report

remember pack backpack
open @pack
wait_action
sleep 1500

# ------------------------------------------------------------- 1. arm ourself
# The katana arrives in the pack from the newbie kit; it has to be equipped
# before it does anything. Both graphics are listed because FLIP=1 items carry a
# DUPELIST and a single-id lookup silently misses the flipped one -- the same
# trap that made a miner's own ore stack invisible in M3.7.
remember blade pack_graphic 0x13FE,0x13FF
require blade

# Layer 1 is LAYER_HAND1 -- the weapon hand. `equip` takes <item> <layer>; the
# first run of this scenario omitted the layer and failed at load with
# "equip needs <layer>", which is the parser doing its job.
equip @blade 1
wait_action
sleep 2000
say armed

# --------------------------------------------------- 2. out to REAL wilderness
#
# NOT A FARM. The previous run went to a Britain farm and the log answered a
# question nobody had asked:
#
#   System: Guards can now be called on you!
#   Basia: Help! Guards a Criminal!
#   Dog: *Dog is attacking you!*
#
# Chickens, dogs and sheep on a farm beside a town are INNOCENT, OWNED animals
# inside a guard zone. Attacking one flags the character CRIMINAL and an NPC
# calls the guards. The bot was not failing to fight -- it was committing a
# crime, and a bot population that hunts livestock would be executed by guards
# rather than fed by them.
#
# That is a behavioural constraint worth more than this proof: legitimate
# hunting means WILD, already-hostile creatures, away from guard protection.
#
# So: open country west of Britain where the world save puts grey and timber
# wolves, well outside the guard zone. A wolf fights back, which is the point --
# it is hostile ALREADY, so no crime is committed and the server has every
# reason to swing.
#
# (1230,1660), not the earlier (1252,1613): the wolf that used to sit at
# (1252,1614) was ENGINE-ASLEEP -- Source-X sector sleep had left it catatonic
# beside the bot, and Fight_CanHit returns WAR_SWING_INVALID for a sleeping
# target, so the server silently dropped every accepted attack (that was the
# whole "ten runs, zero swings" mystery; see huntdbg3 for the awake-wolf
# counterexample). It has since despawned. The wolves the live world holds now
# wander this stretch (console-checked at run time: timber ~(1231,1630), grey
# ~(1256,1690)), and the fact that they MOVE is the proof they tick -- a
# stationary animal in this world is suspect.
use_moongates on
travel_point 1265 1612
wait_travel
expect_travel ok
sleep 2000

say hunting wolves

# --------------------------------------------------------------- 3. find prey
# 0x0019 grey wolf  0x00E1 timber wolf  0x0017 dire wolf  0x0025 white wolf
# 0x003F cougar     0x00D6 panther
#
# THESE ARE READ FROM THE CHARDEF HEADERS, and the previous list was not. It
# said 0x001C for a grey wolf, which is the value generic UO documentation
# gives; this runtime's c_wolf_grey is [CHARDEF 019]. A grey wolf was standing
# next to the bot, attacking it, and `remember prey` bound 0x00000000 because
# the body id never matched. The same guessing put panther at 0x00D5 (really
# 0x00D6) and brown bear at 0x00D3 (really 0x00A7 -- 0x00D3 is a BLACK bear).
#
# Fifth time this milestone that a constant taken from reasoning rather than
# from the shard's own data has cost a run.
#
# Wild predators only, and NOT the farm livestock the previous run chose. These
# are hostile on sight, so attacking one is ordinary hunting rather than a crime.
# Bears are still excluded: a grizzly can beat a fresh character even armed, and
# the question being answered is whether a bot can kill ANYTHING, not whether it
# can win a hard fight.
#
# PATROL, do not stand and scan. Two lessons paid for in characters:
#   - Fighter02 died because an awake wolf chewed on it through three
#     stationary 4-second scan waits (mark_hp read 17 before war even went
#     on). Standing still in predator country is exposure, not patience.
#   - killrun1 aborted on `require prey` while both live wolves were healthy
#     30 tiles away: they wander a HOMEDIST=50 box around their spawn at
#     (1229,1655) (read from the wolf's own save block), and an 18-tile view
#     from one fixed point samples a fraction of that box.
# So sweep the home range and scan at each corner. An awake wolf aggros on
# sight and comes to us, which is the other half of why patrolling works.
# The winning run (killrun3, 2026-08-27 22:09) aimed the first leg at the
# timber wolf's LIVE position read off the server console seconds before
# launch; blind single-point scans had missed wandering wolves twice. This
# committed version sweeps the whole beat instead: the wolves' spawn worldgem
# sits at (1229,1655) with HOMEDIST=50 (read from the wolf's own save block),
# and these legs cross the north-east beat, the home point and the south-west
# beat, so a wolf anywhere in the box passes within view of one leg. An awake
# wolf also aggros on sight and comes to us -- the scan only has to get close.
scan_mobiles
goto 1265 1612
wait_goto
scan_mobiles
sleep 800
goto 1272 1607
wait_goto
scan_mobiles
sleep 800
goto 1229 1655
wait_goto
scan_mobiles
sleep 800
goto 1210 1680
wait_goto
scan_mobiles
sleep 800
goto 1185 1698
wait_goto
scan_mobiles
sleep 800
remember prey mobile_body 0x0019,0x00E1,0x0017,0x0025,0x003F,0x00D6
require prey

# goto_mobile, not travel_entity: travel plans a route to where the mobile was
# AT PLANNING TIME, and animals do not wait there.
goto_mobile @prey
wait_action
sleep 1500

# ------------------------------------------------------------------ 4. kill it
mark_hp

war on
sleep 800
attack @prey
wait_action

# Send the attack ONCE, then only stay in range -- chasing is the bot's job,
# swinging is the server's. 20 x ~2.5s: a katana (11-13) against a 43-HP wolf
# needs ~7 landed hits at Sphere swing speed, and the huntdbg3 run showed a
# full fight resolves in well under a minute once the target actually ticks.
# The window was never the problem in the silent runs -- the target being
# engine-asleep was -- but a real, mutual fight deserves the full minute.
loop 20
  goto_mobile @prey
  wait_action
  sleep 2500
endloop

# The evidence. If the prey is gone from this scan it died, and a corpse
# container is left where it stood. No scenario op asserts "that mobile no
# longer exists", so this is reported as observed evidence read from the log,
# not as a passing assertion.
scan_mobiles
sleep 2500

war off
sleep 1200
say the fight is over

request_skills
sleep 1500
skill_report
sleep 1500
logout
