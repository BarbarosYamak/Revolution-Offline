# NPC price floor for materials — evidence

Owner ruling 2026-09-02: bots MAY sell materials to NPC vendors once the
player-first WTS window has closed. Implemented as a *floor*, gated on a
switch (`econ::SalePolicy::allowMaterialsToNpc`, default ON) **and** on
`playersDeclined`.

Verified 2026-09-02 against `C:\Projects\RevolutionOffline\runtime\scripts`.
Method: parse every `[TEMPLATE VENDOR_B_*]` in `runtime/scripts/templates/`,
resolve template→template `BUY=VENDOR_B_*` includes transitively, then map
each template back to the `[CHARDEF]`s in `runtime/scripts/npcs/` that use it,
then count those chardefs in `runtime/save/*.scp`. Commented rows (`//`,
`////`) excluded — Sphere ignores them.

## Economic reading

The floor as installed is very shallow. It legitimately opens for feathers,
cotton, thread, flax and the three coloured-metal ingots, at 1–2 gp a unit.
It does **not** open for the three materials bots actually stockpile — logs,
iron ingots, ore — because nobody on this shard buys them. That is not a bug
to route around: it means the ruling's second clause ("if no NPC class buys
the item, bank it and cool the goal down") is the *dominant* path, and the
long-term player-market design is unharmed by turning the switch on.

Whoever commented those rows out did so deliberately; re-enabling them is a
server-side change and belongs to `sphere-expert`, not here.

## What changed in the bot

- `econ::SalePolicy{allowMaterialsToNpc=true}`, `CurrentSalePolicy`,
  `SetSalePolicy`, `IsFloorMaterial`, `MaterialFloorOpen`
  (`include/uo/vendor_policy.h`, `src/progression/VendorPolicy.cpp`).
  `IsFloorMaterial` reads the audit matrix (WorldGathered/WorldProcessed)
  plus the `i_ore_`/`i_ingot_` prefixes — the two hue families can never be
  fully enumerated in the matrix.
- `faucet::NpcFloorOpenFor(item, playersDeclined)` — the registry's
  acknowledgement of the floor. `AllowedForItem` is **unchanged and strict**.
- `market::NpcBuyersFor` / `HasNpcBuyer` / `MaySellToNpc` gained a
  `playersDeclined` parameter defaulting to **false**, so every existing
  caller keeps the strict answer.
- `kNpcBuyers` material rows replaced with the verified table above.
- `Runner::PlayersDeclined(item, nowMs)` reads the `no_player_buyer` memory
  event `DoTradeWithPlayer` has been writing all along (Runner.cpp:7902) and
  which nothing read back. Bounded to one hour.
- Three `return true` spins in `DoEarnGold` — "the bank holds a surplus but no
  NPC route", "everything spare is barred", "no NPC trade buys it" — now
  `Cooldown` + `Finish(false)`. Each previously completed with progress 0 and
  was re-picked within milliseconds.
- `ServiceForTrade` gained `weaver → Service::Tailor`, matching
  `AtlasGenMain.cpp:579` and `ClientTravel.cpp:1554`.

`NoteProgress` on a sale was **already** correct and is untouched: it fires
only inside `life::Verdict::Confirmed`, which requires gold in *and* goods out
(Runner.cpp, the `sellSent_` block).

## Limitations

- Shard is down. Everything above is **verified source/script behaviour** plus
  unit tests. No live run has confirmed that a bowyer's 0x9E window actually
  lists feathers, nor what a jeweler pays for a gold ingot.
- The gargish-vendor absence is read off the world save, not off a running
  server.
