## TRAIN-2 (92/98 failed) -- two dominant, structurally distinct causes

### Cause A -- combat archetypes (fencer/macer/archer/warlock/mage), ~60-65
of the 92 failures. DoTrainCombat has NO success return path for a
hunting/casting character (bot/uo-client/src/life/runner/Train.cpp:70-600):
the only "return true" in the whole function (line 453) is gated on
"!WantsToHunt && !caster", i.e. it is dead code for every archetype that
actually fights. A live fight is handed to DoSurvive the instant
obs.underAttack is true (Train.cpp:80), and the kill is confirmed and
looted entirely inside Survive.cpp::ProcessHuntAftermath (line 36,
session_.kills++, "hunt: confirmed kill target=..."). Nothing on that path
ever sets the goal's .progress field, so Core.cpp:2151's
"goal_completed=%s progress=%d" always logs under SURVIVE with progress=0
-- never under TRAIN_COMBAT/TRAIN_AT_NPC/PRACTICE_SKILL, the only three
names TRAIN-2's regex accepts (grade_life.py:213).

  - Evidence: Hector had 4 real kills ("hunt: confirmed kill",
    Hector.console.txt) and Leander had 6 (Leander.console.txt), yet both
    read "verified training events 0"; goal_completed=TRAIN_COMBAT does
    not appear once in either console log.
  - Corroborating: grep -c "goal_completed=TRAIN_COMBAT" is 0 across all
    10 sampled combat chars (Hector, Aelven, Faustus, Neros, Titus, Wynven,
    Dravys, Alder, Aurelius, Leander).
  - Owner/subsystem: bot-core, runner/Train.cpp + runner/Survive.cpp
    goal-kind attribution. Handler defect (missing completion signal), not
    a need-scoring defect -- combat does happen for a minority (Hector,
    Leander, Titus partial), it is just never reported as TRAIN_COMBAT
    progress.
  - Also explains why fights so rarely even start for the other ~55:
    HandOffFromHunt chains (UPGRADE_GEAR / ReplaceEquipment / bandages /
    reagents) precede every hunt attempt and frequently never clear before
    SURVIVE/cooldowns consume the session, e.g. Faustus
    (Faustus.console.txt:920 x11, "nothing is here to practise combat on"),
    Hector (Hector.console.txt:2635, "no hunting ground reachable after 3
    trips").

### Cause B -- "Working" skills never generate a training need at all
(tailor, merchant_tinker, and most of full_crafter/scribe/alchemist's core
skill), ~25-30 of the 92. Needs.cpp:1970 (HowToPractise):
"if (how == PracticeBy::Working) continue;" -- by design, a skill whose
practice mode is "raised by the profession's own work" (Tailoring,
Tinkering, Smithing, Inscription, Alchemy) never adds NeedTraining, so it
never runs TRAIN_AT_NPC/PRACTICE_SKILL and never logs "train:"/"practice:".
Skill gain instead happens silently as a side effect of CRAFT/MINE/SMELT
completions, which TRAIN-2's regex does not accept.

  - Evidence: Rhaler (full_crafter) TRAIN-1 shows a real gain,
    "skills 100.0->150.4" (Rhaler.grade.txt), from 22 MINE completions and a
    CRAFT loop -- genuine training happened -- but TRAIN-2 reads "verified
    training events 0" because none of it ran through TRAIN_AT_NPC/
    PRACTICE_SKILL. Same shape for Ghalor (100.0->150.1) and Kharain's
    partial CRAFT-driven gain.
  - Aelia (tailor): 0 hits for TRAIN_AT_NPC/TRAIN_COMBAT/PRACTICE_SKILL in
    the whole console -- the need is architecturally never raised for her
    build's skill set this session.
  - This is a grader/measurement gap, not proof of a runtime defect --
    TRAIN-1 (real before/after skill delta) is the correct instrument here
    and it PASSES for these three (Rhaler, Ghalor, and lumberjack Halain);
    TRAIN-2's vocabulary is simply blind to work-based skill gain.

  - Separately, a genuine defect surfaced by this same comparison: Selene
    (alchemist) reads TRAIN-2 PASS (10 "verified" TRAIN_AT_NPC/
    PRACTICE_SKILL completions) but TRAIN-1 is flat, "120.8->120.8"
    (Selene.grade.txt) -- 10 goals reported success with zero measured skill
    movement. That direction (goal claims success, skill does not move) is
    the one worth root-causing next; owner: bot-core, runner/Train.cpp
    DoTrainAtNpc/DoPracticeSkill completion gating.
  - For the remaining crafters where NO skill moved AND no training goal
    ever ran (Aelia, Kharain both flat 100.0->100.0/121.5->121.5 with 0
    TRAIN* goal picks), the root cause is Cause C below (the character never
    reached its own faucet at all), not Cause B.

Grader footnote (not counted toward the 92, but explains a related
mismeasurement): FARM-2's "hunt" clause looks for a "hunt: killed '" line
(grade_life.py comment cites "Runner.cpp:2913") that does not exist anywhere
in bot/uo-client/src/ -- the runner split renamed it to
"hunt: confirmed kill target='%s'" (Survive.cpp:36) and the grader's grep
was never updated. Sample macer/warlock chars had 0 confirmed kills anyway,
so this did not change any verdict in the sample, but it would silently
undercount FARM-2 for any hunter that does land kills.

## FARM-2 (86/98 failed) -- three causes, same order of coverage

### Cause A (shared with TRAIN-2 Cause A) -- combat archetypes, ~55-60 of 86.
fencer/archer/mage (gathers="") need gold_b > gold_a or a CRAFT/EARN_GOLD/
SMELT completion; macer/warlock/pk (gathers="hunt") need a confirmed kill or
rising gold. Both faucets are the same hunt loop, and Cause A above shows it
rarely completes or nets income: gold falls because supply purchases
(bandages, reagents, armor) run every session while the hunt itself stalls
on hand-offs, crowd-avoidance stand-downs, or unreachable hunting grounds.

  - Evidence: Faustus gold 7611->7323 kills 0; Neros 10000->9736 kills 0;
    Dravys 10000->9931 kills 0; Alder 10000->8632 kills 0; Titus
    5767->5459; Aurelius 6155->6155 (flat); Leander 9444->8159 despite 6
    confirmed kills logged (loot value too small / bandage-buy spend
    exceeds it).

### Cause B -- gathering archetypes with no seeded resource ("no known
source of that resource"), lumberjack_swordsman specifically: Vorar
(Britain-homed lumberjack) hits goal_blocked=GATHER_LOGS reason="no known
source of that resource" 131 times (Vorar.console.txt:862+) and never
gathers a single log (logs=+0). Halain, the other lumberjack sample, is
Yew-homed and travels straight to a known "Yew carpenter"/forest and
passes (logs=+19). SeedNewbieKnowledge (Core.cpp:957) seeds a resource
lead from state_.homeCity, so a lumberjack whose assigned home city has
no seeded log source is stuck with no fallback discovery -- there is no
explore-to-find-a-forest path once the seed misses, unlike hunting grounds
which fall back to Atlas::NearestHuntingGround.

  - Owner/subsystem: bot-core, life/newbie_knowledge seed data /
    Professions.cpp home-city list for lumberjack_swordsman, or add an
    atlas-driven fallback the way TrainCombat has one.

### Cause C -- tailor's wool faucet never starts: Aelia
goal_failed=MAKE_CLOTH reason="no sheep found after 4 trips to the
pastures" (Aelia.console.txt:2851) -- travel/atlas cannot route to a
sheep pasture. Amara (the other tailor sample) never even attempts
HARVEST_WOOL/MAKE_CLOTH/CRAFT this session (only 1 goal_completed line,
TRAIN_AT_NPC) -- a starvation/priority issue (need never wins the pick),
distinct from Aelia's navigation failure. Both land on FARM-2 FAIL for
different reasons; owner: travel/atlas for Aelia's case, planner/need
scoring for Amara's.
